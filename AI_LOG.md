# AI_LOG.md

## Использованные AI-инструменты

**Инструмент:** ChatGPT (OpenAI, GPT-6).

AI использовался в процессе разработки Runforge Dashboard как технический помощник для обсуждения решений, объяснения новых концепций, проверки кода, стилизации компонентов и написания тестов.

Больше всего AI помог с тестами, т.к. я впервые работал с ними.

## Примеры полезных запросов

### 1. Разбор автоматизированных тестов

**Запрос:**

> Объясни прям по частям подробно что происходит во втором тесте, прям бери кусок кода и объясняй.

**Результат:**

ChatGPT объяснил работу моков Vitest, асинхронного ожидания элементов, имитации действий пользователя и проверок React Testing Library.

Это помогло разобраться в принципах тестирования пользовательских сценариев и реализовать проверки поиска, фильтрации и навигации.

### 2. Разбор cleanup в useEffect

**Запрос:**

> Приведи на конкретном примере зачем мне нужен cleanup.

**Результат:**

ChatGPT объяснил проблему race condition при асинхронной загрузке данных и показал, как cleanup позволяет игнорировать результаты устаревших запросов.

После изучения примера в `RunsPage` была добавлена cleanup-функция для защиты от обновлений состояния устаревшими асинхронными операциями.

## Ошибка в рекомендации AI

При реализации повторной загрузки данных ChatGPT предложил сбрасывать состояния `isLoading` и `error` непосредственно внутри `useEffect`.

Пример предложенного подхода:

```tsx
useEffect(() => {
  setIsLoading(true);
  setError(null);

  // Загрузка данных
}, [retryCount]);
```

**Проблема:**

ESLint выдал предупреждение `react-hooks/set-state-in-effect`, связанное с синхронными обновлениями состояния внутри эффекта.

Этот вариант создавал лишний цикл обновления компонента и не соответствовал рекомендациям используемых правил React Hooks.

**Исправление:**

Сброс состояний был перенесён в обработчик пользовательского действия `handleRetry`.

```tsx
const handleRetry = () => {
  setIsLoading(true);
  setError(null);
  setRetryCount((prev) => prev + 1);
};
```

Сам `useEffect` остался ответственным за асинхронную загрузку данных и обработку её результата.

После исправления код был повторно проверен.
